# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Existing Vite + React + JavaScript application using Axios, Tailwind CSS, and the JSONPlaceholder posts API.

## Users

The primary user is someone who wants to browse and explore posts easily using search, filters, sorting, pagination, and Card, List, and Table views.

## Product Purpose

Post Explorer is a polished frontend demonstration that makes a collection of posts easy to browse and inspect. Success means the experience demonstrates strong React/frontend implementation and UI/UX skills while remaining smooth, modern, vibrant, professional, and easy to use.

## Positioning

The product combines one post dataset with multiple useful exploration modes—search, filtering, sorting, pagination, and genuinely distinct card, list, and table views—inside a cohesive editorial interface rather than a generic dashboard.

## Operating Context

Users load the web application, wait for posts to be retrieved from JSONPlaceholder, then browse the transformed results. They may search across post content, narrow results with category or author filters, sort the collection, choose how many items to see, change view modes, and switch between light and dark themes.

## Capabilities and Constraints

- Use Vite + React + JavaScript; do not introduce TypeScript or Next.js.
- Use Axios for API fetching; do not replace it with `fetch()`.
- Use the JSONPlaceholder posts API as the source dataset.
- Preserve search, filtering, sorting, pagination, rows/items per page, Card/List/Table views, responsive design, and scrollable content where appropriate.
- Preserve dark mode, light mode, theme persistence, and view mode persistence.
- Provide loading, error, and empty states.
- Provide smooth animations and micro-interactions without breaking accessibility or performance.
- Keep the codebase clean, reusable, component-based, and commit-ready.
- Do not remove or break existing functionality.

## Evidence on Hand

The application uses live records from `https://jsonplaceholder.typicode.com/posts` and transforms them in JavaScript for display. No testimonials, customer claims, deployment claims, or external brand assets should be fabricated.

## Product Principles

- Make browsing effortless.
- Let users choose the way they inspect information.
- Keep interaction feedback clear and smooth.
- Favor distinctive, intentional UI over generic dashboard patterns.
- Preserve working behavior while improving craft and maintainability.

## Accessibility & Inclusion

The web interface should remain responsive and keyboard-accessible, with readable contrast, visible focus states, semantic controls, and reduced-motion support.

## Visual commitments

The user pinned the Frozen lake palette: Slate #6D8196, Ice #ADD8E6, Snow #FFFAFA, and Navy #000080. Use these exact source swatches with derived tints for readable contrast and Snow as the default background. Keep Crimson Text headings and Instrument Sans body text and controls. Preserve the collapsible library, independently scrollable views, and inline full post details. Provide persisted Compact, Comfortable, and Spacious density across all views, compact top spacing, and subtle ambient mist and loading shimmer controlled by an Ambient motion toggle and system reduced-motion preferences. Keep the removed library note and its icon absent.
